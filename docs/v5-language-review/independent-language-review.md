# v5 报告语言自然度独立检查

检查对象：`output/v5/20261022-docker-lab-report-v5.docx`。

本次依据 `docs/v5-language-review/officecli-text.txt` 全文检查正文段落；该提取文件的表格仅显示占位符，表格单元格措辞不在本次检查范围内。仅检查语言，不修改报告、不联网、不重跑实验。

## 总体判断

正文的实验步骤、命令解释和结果描述整体清楚，技术名词的使用也基本自然。较值得修改的是版本修订说明、截图加工说明、对“真实”“实际”的重复强调，以及几句直接回应审核顾虑的话。这些表达容易让报告显得像经过多轮审稿拼接的交付说明，削弱学生实验报告本身的连贯感。单凭这些措辞不能判断作者身份，也不能给出可靠的 AI 检测概率。

建议局部精简，保留实验结果、不同轮次的版本与端口，以及必要的资料缺失说明；不需要把全部技术说明改成口语。

## 优先修改的 8 处

### 1. 摘要混入文档版本维护说明

- 位置：封面后摘要，`paraId=63C858E2`。
- 原句：`v5规范文档结构及排版，三轮实际版本、端口和结果分别保留。`
- 问题：这是对本次文档制作工作的说明；“三轮实际版本”搭配也不自然。摘要应交代实验内容与记录范围。
- 建议：删除此句，或将其移入过程文档。前两句已经说明正文与两个附录分别记录哪次实验，不会因此丢失轮次信息。

### 2. 普通实验操作中重复强调真实性

- 位置：4.2 容器中的真实游戏操作，`paraId=3D686D3F`。
- 原文：`在实际应用容器中通过浏览器完成轻松难度一局，保存昵称“6085实验”。本次演示记录为 12 步、6.95 秒，记录编号 1。这些数值来自服务端实际返回，仅用于展示成绩保存流程。`
- 问题：“实际应用容器”“实际返回”重复自证；“保存昵称”省略了保存成绩这个动作；末句有解释过度的观感。
- 建议改为：`在容器中通过浏览器完成轻松难度一局，以昵称“6085实验”保存成绩。服务端返回的记录编号为 1，成绩为 12 步、6.95 秒。`
- 连带建议：本节标题可改为“容器中的游戏操作”。“真实”不是这个标题需要承担的技术含义。

### 3. 验证结果写成抽象的验证过程

- 位置：8.1 启动与端口问题，`paraId=1911E03C`。
- 原句：`恢复后以 Client 与 Server 响应以及实际容器结果验证环境可用。`
- 问题：“以……响应以及……结果验证……”名词堆叠，读起来生硬；直接写观察到的结果更清楚。
- 建议改为：`恢复后，Client 与 Server 均能响应，容器也可正常运行。`

### 4. 文件校验后的结论搭配生硬

- 位置：A3 容器运行与交付文件校验，`paraId=6270524A`。
- 原文：`分别计算交付JAR与容器/app/app.jar的SHA256，两个结果完全一致。这将本轮交付文件与实际部署镜像直接对应。`
- 问题：“这将……直接对应”不符合自然搭配；前一句已经说明校验结果，后一句再抽象解释没有增加信息。
- 建议改为：`分别计算交付 JAR 与容器内 /app/app.jar 的 SHA256，结果一致。`
- 技术边界：这里应保留对 JAR 文件的校验，不应把它改写成镜像整体摘要相同。

### 5. 实验结果中插入独立预览文件的制作信息

- 位置：A4 实际游戏与成绩保存，`paraId=3E298FFB`。

- 建议：报告保留第一句的实验信息；后一句移至过程文档或配套预览文件说明。第一句可顺为：`该轮同时采集了宽 1440 的桌面页面和宽 375 的手机页面，手机页面未出现横向溢出；截图保留于证据包 linux-v3 目录。`

### 6. 截图来源说明混入图片加工和自证话语

- 位置：A10 补充证据来源与版本对应，`paraId=53698D40`。
- 原文：`正文图1至图11沿用原Windows实验的真实截图；本附录图A1a、图A1b及图A2至图A9来自2026年10月21日Linux补充实验。终端图为实际窗口采集，浏览器图来自当次应用容器。图A1a在Word内仅裁去底部空白显示区，内嵌原PNG字节未改；所有关键命令与返回完整保留。`
- 问题：来源记录有价值，但“真实截图”“实际窗口”“原PNG字节未改”连续强调，让说明呈现为对审核疑虑的回应。Word 裁切与内嵌字节属于制作过程信息。

- 建议改为：`本轮源码镜像 JAR 与交付 JAR 的整包摘要不同，但 BOOT-INF 内的应用类、前端资源和依赖逐项相同。完整命令、删除检查及输出收录在证据包 windows-localtest-20261022 目录中。`

## 建议保留的技术表达

- “镜像、容器、Registry、命名数据卷、持久化、健康检查、同源、JAR、SHA256、JSON、BOOT-INF”等承担具体技术含义，本身不是语言问题。
- 容器重建前后比较标识、完整排行榜 JSON、镜像摘要和 JAR 摘要是实验验证所需；应减少重复的“真实、实际、完整”等修饰，不应删除验证对象或混淆不同校验层级。
- 第三章关于“已保存成绩”和“未完成牌局”的范围区分清楚，应保留。
- 对原 Windows 安装全过程资料缺失的说明应至少保留一处；语言精简不能把缺失资料写成已完成的实验。
